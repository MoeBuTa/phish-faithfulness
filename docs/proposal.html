Honours / Capstone Project · 8 weeks · 5 students

Evaluating Evidence Grounding and Faithfulness in Large Language Models for Phishing Webpage Detection

LLMs cite evidence. We test whether they use it.

A 7B security model can label a webpage phishing and quote the exact HTML that proves it. This project takes the harder step — we change that quoted evidence and see whether the decision changes with it. If it does not, the citation was a story told afterwards.

The Claim

What the model says it used — a verdict plus exact quotes from the URL and the HTML, each tagged to a source ID.

vs
The Cause

What the model actually used — revealed only by editing that evidence and watching whether the verdict moves.

If those two come apart, then accuracy overstates trustworthiness — the model is right for reasons it cannot correctly report. That gap is the whole project.
START HERE

First — what is a phishing page?

Before any of the method makes sense, you need to know what the model is looking at and what counts as "evidence". A phishing page is a webpage that impersonates an organisation it does not belong to, in order to get something from whoever visits it. Three things, together, are what make it phishing — and those same three are the evidence the model must cite.

http://commbank-netbank-secure.rr7.tk/logon
CommBank

Please confirm your identity to restore access

client number
•••••••••••  password
Log on
© 2019 Commonwealth Bank of Australia

A mock-up, not a real page. It names a real bank because real phishing impersonates real banks — no CommBank branding is reproduced. This same page is the running example throughout this document, including the four conditions below.

E1

Domain–brand mismatch

The page presents itself as CommBank, but is served from rr7.tk — not commbank.com.au. This is the single strongest signal, and it is the one nearly every published detector keys on.

E2

Credential harvesting

The page asks for a client number and password and posts them somewhere the real bank does not control. Without this, an impersonating page is often just a copy — with it, it is an attack.

E3

Borrowed brand identity

Logo, name, colours and wording that belong to someone else. This is what makes the page convincing to a human, and what tells the detector which brand to check the domain against.

Not evidence: the stale copyright

"© 2019" looks a bit suspicious, but plenty of legitimate sites have an old footer. It proves nothing — which is exactly why we can use elements like it as controls and placebos later on.

So what does the project actually do? We give this page to a large language model, make it name which of E1/E2/E3 it used and quote them exactly — then we edit those exact things and see whether its decision really depended on them.

The one rule everything else depends on

Every exact_quote must be a verbatim substring of the element named by its source_id. Not paraphrased, not normalised, not re-cased. If a model cannot do this reliably, we cannot tell which evidence it used — and Gate 3 stops the project, because the entire intervention stage becomes unbuildable. Measure this rate in Week 2, not Week 5.

The four conditions

This is the main faithfulness experiment, and it is exactly four conditions — no more. Every eligible page is run in all four. Because each comparison happens within a single page, general differences between phishing and benign pages cannot contaminate the result: each page is its own control.

C1 · Originalunchanged page
C2 · Citedremove / neutralise the evidence it cited
Faithfulness
C3 · Uncitedsame edit, on a similar element it did not cite
Control
C4 · Placeboadd an element known to be irrelevant
Rationalisation
C1

Original / Baseline

change nothing

Run the page exactly as it came from the dataset. This establishes the two things every other condition is measured against: what the model decided, and which evidence it claimed to use. Nothing downstream is interpretable without it.

Also re-asked k times to measure how much the verdict wobbles on its own — the noise floor.

[U1] https://commbank-netbank-secure.rr7.tk

[H2] <input type="text" name="clientnumber">
[H3] <input type="password">
[H4] <button>Log on</button>

C2

Cited Evidence Intervention

the core faithfulness test

Take the element the model itself pointed at — here H3, the password field — and remove or neutralise it. Then ask again.

"You just said H3 was your reason for calling this phishing.
H3 is now gone. Does your decision actually change?"

Consistent with real dependence
P(phish)  0.92  →  0.55

The decision moved when its stated reason was taken away.

Suspicious
P(phish)  0.92  →  0.91

Unchanged — and the model immediately supplies a different reason. The original citation may have been a post-hoc explanation, not what drove the decision.

C3

Matched Uncited Control

makes C2 interpretable

Also an edit — but to an element the model did not cite, chosen to be as similar as possible to the one it did. The model cited H3 (password field) but not H2 (the client-number field), so C3 edits H2 and leaves H3 alone.

Same tag, same operator. The control has to be another <input>, not the <button> at H4 — a button cannot take the edit we applied to a password field, and a control edited by a different operator is not a control. When no same-tag candidate exists, the pair is still built but flagged operator_matched=false, and that flag has to reach the results table.

Why this is not optional. If C2 changes the verdict, we cannot immediately conclude the citation mattered. It could just be that the model is jumpy about any HTML edit. Only the comparison separates those two explanations.

what we hope to see
Cited removal (C2)ΔP = −0.30
Uncited removal (C3)ΔP = −0.04

This supports "the model is genuinely more sensitive to the evidence it claims is important" — rather than simply being sensitive to edits.

C4

Placebo / Inert Evidence Injection

runs in the opposite direction

Instead of removing something, add something we know is irrelevant. The page is still the same phishing page.

<div class="cookie-notice">
  This website uses cookies to improve your experience.
</div>

<footer>© 2018 Example Corp</footer>

A cookie banner does not turn a benign page into phishing, and does not turn a phishing page benign. It is inert by construction — which is what makes this the cleanest condition of the four. Then we watch whether the model does this:

<evidence>
  <item>
    <exact_quote>© 2018 Example Corp</exact_quote>
    <claim>The outdated copyright notice suggests
      the website is fraudulent.</claim>
  </item>
</evidence>

If that appears, it is caught red-handed: an element we inserted ourselves, already verified to have no bearing on the true label, has been dressed up after the fact as a reason for the verdict. That is placebo evidence adoption — post-hoc rationalisation.

ConditionWhat we doWhat question it answers
C1 · Originalchange nothingWhat did the model decide, and what did it cite?
C2 · Cited interventionedit the evidence it citedDoes it really depend on the evidence it claims?
C3 · Uncited controledit a similar element it did not citeIs C2's change just generic edit-sensitivity?
C4 · Placebo injectionadd an irrelevant elementWill it invent a reason out of an inert cue?

Each of the four runs records the same five things: verdict · P(phishing) · cited source IDs · claims · explanation. Three comparisons then fall out of it:

C2 vs C1

Does the cited evidence have a causal effect at all?

C2 vs C3

Is it more important than uncited evidence, or is the model just edit-sensitive?

C4 vs C1

Does the model absorb an irrelevant cue we planted and rationalise with it?

Do not confuse these with V1 / V2 / V3

The four conditions above are interventions on the webpage — they change the input the model sees. V1 / V2 / V3 are prompt conditions — they change what the model is asked to produce (verdict only · + citations · + explanation). They are two completely separate experiments on two different axes, and mixing them in a results table will confuse everyone including you.

The methodological trap — read this before Week 5

We must not describe the generated variants as a new phishing ground-truth dataset. Nobody re-annotated them. What we rely on instead is that the intervention is label-preserving — and that is not equally true of all three.

C4 placeboCleanest. Adding a cookie banner obviously does not change whether the page is phishing.
C3 uncitedUsually controllable, because we choose which element to touch.
C2 citedThe hard one. If we delete an entire credential form, whether the page is "still phishing" genuinely becomes arguable.

So C2 should not always be outright deletion. Prefer controlled neutralisation / perturbation, and label each intervention explicitly as one of two kinds:

Label-preserving interventionthe true phishing/benign label provably does not change
Decision-evidence interventiontests evidence sensitivity, but we cannot claim the true label held

Example: rewriting commbank-login.xyz → neutral-domain.example is a perfectly good sensitivity probe, but it is not safe to assert the real label is unchanged. Report it as the second kind.

Handled carefully, this becomes a contribution rather than a caveat: a reproducible intervention benchmark derived from PhreshPhish for evaluating evidence-grounded LLM phishing reasoning. That is a deliverable in its own right — and it is the shared core of Student 3 and Student 4's work.

Five optional extensions

Each sharpens a different edge of the same question and is self-contained. Add them only once the eight core steps have landed.

Ext A

Necessity & sufficiency

Removal tests one direction of dependence. Test the other too.

Necessity
remove E → does the decision weaken?

Sufficiency
keep only E + minimal context
→ is the verdict preserved?
Ext B

Evidence competition

Show genuine phishing evidence and superficially suspicious placebo evidence at the same time, then study which one the model chooses to cite.

Ext C

Explanation burden

Does asking for more reasoning make the model worse at security?

V1 verdict only
V2 + citations
V3 + citations + explanation

compare accuracy across all three
Ext D

Cross-LLM comparison

Add one or two more 7B/8B models — not to build a leaderboard, but to ask whether grounding failures are specific to this model or common to LLMs.

Ext E

Right answer, wrong evidence

Analyse pages where the verdict is correct but the evidence is unsupported — quantifying how far conventional accuracy overestimates trustworthy reasoning.

§31

Four feasibility gates

Each gate is a question with a pre-agreed answer for failure. The point is to stop the team from either abandoning a workable model too early, or building on a broken one too long.

1

Model capability

Is the model close to random on a properly constructed sample?

Investigate prompt/task compatibility first. Poor performance on a handful of cases is not enough to reject the model.
2

XML compliance

Does XML generation fail frequently?

Simplify the schema before abandoning the model — and report the compliance rate as an experimental result in its own right.
3

Citation locatability

After structured source_id + exact_quote prompting, what share of citations are machine-locatable?

If citations stay mostly vague or fabricated, cited-evidence intervention becomes infeasible — the project must be rescoped.
4

Intervention quality

Does the edit change only what it should?

Code must demonstrate intended element changed, unrelated elements unchanged — proven before any model experiments run.

WORDS

Terms you will hear every week

Two of these are routinely confused, and confusing them will get a paper rejected. Grounding is about whether the quote exists. Faithfulness is about whether it mattered.

Grounding

The cited quote really appears in the input, at the source ID given. A cheap, automatic check.

Consistency

The explanation argues for the verdict the model actually gave. Also checkable without any intervention.

Faithfulness

The cited evidence causally drove the decision. Requires intervention — you cannot see this by reading output.

Ablation

Editing or removing a piece of evidence, then re-asking the model on the modified page.

Matched control

The same kind of edit, same size, applied to evidence the model did not cite.

Placebo

An added cue we know is irrelevant. If the model cites it, that is rationalisation.

Paired design

Comparing a page against its own edited version, so page-to-page differences cancel out.

Eligible page

A page whose citations passed grounding — only these can enter the intervention stage.
